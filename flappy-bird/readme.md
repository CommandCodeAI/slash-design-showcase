## Method

**Static read:** all 5,607 lines across these seven files read directly, no skimming. Every claim below is cited by file and line number.

**Manual playtest (Fable 5, GLM 5.2, DeepSeek only):** each of these six files was actually played, not just read: flapping with both the Space/Arrow keys and tap/click, deliberately flying into pipes and into the ground to trigger death, running the restart flow, and checking how each one behaves when the browser window is resized.

**Automated crash check (Fable 5, GLM 5.2, DeepSeek):** an attempt was made to drive all six through real headless Chrome (`agent-browser`), which failed in this sandbox (missing `libasound.so.2`, no passwordless `sudo`). As a fallback, a Node `vm` shim (stubbed `window`/`canvas`/`localStorage`/`requestAnimationFrame`) executed each file's actual script through 600 simulated frames of play, and counted canvas calls as a rendering-cost proxy. All six ran clean: 0 load errors, 0 runtime exceptions.

**Automated crash check (kimi-k3, GPT-5.6 Sol):** the same Node `vm` shim approach was repeated for these two when they were added, run for ~330 simulated frames (including simulated flap key-presses partway through to exercise the play state, not just the idle start screen). Both ran clean, 0 load errors, 0 runtime exceptions. GPT-5.6 Sol averaged ~261 canvas draw calls/frame; kimi-k3 averaged ~541/frame, roughly double, consistent with its heavier particle/parallax/medal-UI rendering. Neither of these two was hand-played in a real browser for this update — see Limitations.

**Automated crash check (Opus 5):** same shim, 330 simulated frames, with flap key-presses and canvas `mousedown` fired from frame 30 onward and a `resize` event injected at frame 120 to exercise the fit path mid-play. Clean: **0 load errors, 0 runtime exceptions**, loop never stalled. It averaged **~626 canvas draw calls/frame** — the heaviest in the set, above kimi-k3's ~541 and roughly 2.4x GPT-5.6 Sol's ~261. That is a rendering-cost proxy, not a measured frame time: the count is driven by its per-frame procedural terrain (both parallax hill layers redraw ~110 `lineTo` segments each at `hills()`, `opus-5/index.html:273-281`) plus the scalloped-grass arc loop in `ground()` (`opus-5/index.html:317-322`). Cheap primitives, but a lot of them. Opus 5 was not hand-played in a real browser for this update — see Limitations.

This only proves the logic doesn't crash; it isn't a substitute for an actual hands-on playtest.

## Findings

- **Collision math is now an even 3-3 split between the exact test and the AABB approximation.** GLM (`GLM-5.2/index.html:294-299`), GPT-5.6 Sol (`gp-5.6-sol/index.html:185-191`), and kimi-k3 (`kimi-k3/index.html:179-184`) all independently converged on the same textbook clamped circle-vs-rect distance test — the only exact implementation, and GPT-5.6 Sol and kimi-k3 both apply their own forgiveness margin on top of it (GPT-5.6 Sol shrinks the bird's collision radius by 5px at `gp-5.6-sol/index.html:252-253`; kimi-k3 hardcodes a hitbox radius of 14 against a ~18px visual radius, `kimi-k3/index.html:73`, with a comment explicitly calling it "forgiving on purpose"). Fable5 (`Fable-5/index.html:285-292`) and Opus 5 (`opus-5/index.html:231-236`) both approximate the circle as an inscribed, shrunk AABB (cheap and fine) — Opus 5's `hit()` is the tersest version in the set at six lines, early-returning on the x-overlap test and shaving 1.5px off the bird radius as its forgiveness margin. DeepSeek (`DeepSeek-V4-Pro/index.html:221-234`) uses the bird's full visual bounding box with no forgiveness margin: correct, but the least tuned.
- **Confirmed bug, DeepSeek:** canvas backing store is fixed at 420×640 (`DeepSeek-V4-Pro/index.html:68-70`), no `resize` listener anywhere, but its own CSS switches the wrapper to `100vw/100dvh` under 440px width. Any modern phone (aspect ≈0.46) stretches the fixed 0.656-aspect canvas non-uniformly.
- **Resize handling is now a spread, not a tie.** Fable5, GLM, and DeepSeek all read `devicePixelRatio` once, but only Fable5 and GLM re-run their fit/resize function on a `resize` listener (`Fable-5/index.html:75`, `GLM-5.2/index.html:75`), so both letterbox correctly on an actual resize. kimi-k3 does the same thing more thoroughly: a virtual-resolution `resize()` (`kimi-k3/index.html:50-63`) scales the canvas backing store by `devicePixelRatio` *and* remaps drawing coordinates via `ctx.setTransform`, and it's the only one of the five that also resets its frame-timing reference on `visibilitychange` (`kimi-k3/index.html:283`) so returning to a backgrounded tab doesn't cause a giant simulated-physics jump on the next frame. GPT-5.6 Sol takes a different route entirely: no JS resize listener and no `devicePixelRatio` scaling at all, relying purely on a CSS `aspect-ratio: 9/16` wrapper plus a stretched `width:100%/height:100%` canvas (`gp-5.6-sol/index.html:23-37`). That avoids DeepSeek's distortion bug (the aspect ratio can't drift, since it's locked by CSS, not by JS math), but the 540×960 backing store never gets sharper on a high-DPI or larger display, so it will look softer than the other four when stretched up. **Opus 5 lands closest to kimi-k3 here**: `fit()` (`opus-5/index.html:63-73`) scales the backing store by `devicePixelRatio` *capped at 2.5* — the only build in the set that bounds DPR, which stops a 3x-DPR phone from allocating a 1200×1800 buffer for a 400×600 game — remaps coordinates via `ctx.setTransform`, letterboxes with a CSS `min()` fit against both axes, and re-runs on `resize`. It has no `visibilitychange` handler like kimi-k3, but it doesn't need one: the loop clamps `dt` to `1/30` on every frame (`opus-5/index.html:486`), so returning to a backgrounded tab produces one slow frame instead of kimi-k3's explicitly-reset timer or a physics blowup. That clamp is the more robust of the two approaches — it also covers GC pauses and slow frames, not just tab restores.
- **Audio is now 3-3, and mute is 2-4.** GLM, kimi-k3, and Opus 5 all synthesize sound in-code via `AudioContext` oscillators (GLM: 4 effect functions at `GLM-5.2/index.html:108-129`; kimi-k3: 5, at `kimi-k3/index.html:88-115`; Opus 5: a single parameterized `beep(freq, dur, type, vol)` at `opus-5/index.html:109-121`, called three ways — a triangle-wave flap, a sine score chime whose pitch rises with score up to a cap of 12, and a sawtooth death tone). Opus 5's is the most compact implementation, lazily constructing the `AudioContext` on first sound and wrapping the whole body in a `try/catch` so an autoplay-policy rejection can't break the game loop. **GLM and Opus 5 are the only two with a mute toggle** (`GLM-5.2/index.html:689,775`; `opus-5/index.html:33-40,104-108` — a real focusable `<button>` with `:focus-visible` styling and `stopPropagation` so hitting mute doesn't also flap the bird, the most accessible of the two). kimi-k3's sound has no in-game way to turn it off. GPT-5.6 Sol has no audio at all: no `AudioContext`, no sound calls anywhere in the file, the only one of the six that's fully silent. On adaptive difficulty, Fable5 was alone among the original three; GPT-5.6 Sol, kimi-k3, and Opus 5 all ramp with score too (`gp-5.6-sol/index.html:144,240,243`; `kimi-k3/index.html:224-225`; `opus-5/index.html:133-134,196` — Opus 5 ramps three things rather than two, tightening pipe speed 158→232, gap 162→132, *and* spawn interval 1.42s→1.14s).
- **Persistence is 4-2.** GLM, DeepSeek, GPT-5.6 Sol, and kimi-k3 all persist a best score via `localStorage` (`gp-5.6-sol/index.html:76,181`; `kimi-k3/index.html:122,250`). Fable5 never persists a best score — it only saves the day/night theme choice. **Opus 5 is the other miss, and it's the clearest gap in an otherwise complete build**: it tracks `best` and renders it prominently on the game-over card next to the run score (`opus-5/index.html:126,242,439-442`), even firing a "new best!" headline, but the variable is plain in-memory state that resets on reload. There is no `localStorage` call anywhere in the file. The UI promises persistence the code doesn't deliver — a one-line fix, but as shipped the "best" column is best-this-session.
- **Gemini 3.6 Flash needed real iteration to get playable (user-reported, not independently verified against draft history):** the one-shot output had the bird falling/jumping wrong, and it took 5-6 follow-up prompts to fix — the only model in this benchmark that needed that kind of correction cycle, matching the same struggle this repo's brick-breaking benchmark saw from this model (4-5 prompts there). What it landed on has a cute UI, by the user's own account, so the iteration bought a real visual payoff even though the physics took work to nail down. Only the final kept file was read for this update — the broken intermediate drafts weren't available to cite directly, so this finding rests on the reported history rather than a diff.
- **kimi-k3 has a harmless dead-code leftover.** Its `dead` state loop includes `for (const p of pipes) p.x -= 0; // world freezes on death` (`kimi-k3/index.html:378`) — subtracting zero does nothing, and pipes already don't move in that state because the pipe-scroll logic only runs under `if (state === 'play')` (`kimi-k3/index.html:342-356`). It reads like a stale artifact of an earlier draft rather than a bug with any visible effect.
- **Offline-safety is now an even 3-3.** Fable5, GLM, and kimi-k3 all pull a Google Fonts stylesheet over the network (`kimi-k3/index.html:7-9` loads "Baloo 2", the same family Fable5 uses). DeepSeek, GPT-5.6 Sol, and Opus 5 are fully offline-safe — no external requests of any kind (verified by grep: no `<link>`, no `fetch`, no `XMLHttpRequest`, no `@import` in any of the three).
- **Opus 5 wants "Baloo 2" but never loads it — deliberate-looking, and the right call.** Its CSS and every canvas `font` string request `'Baloo 2'` first (`opus-5/index.html:20,403,433`), the same family kimi-k3 and Fable5 fetch from Google Fonts, but Opus 5 ships no stylesheet link. Instead every declaration carries a full fallback chain — `'Baloo 2','Comic Sans MS','Trebuchet MS',system-ui,sans-serif` — so on a machine without Baloo 2 installed it renders Comic Sans, which is a defensible substitute for a "cute" brief and costs nothing offline. This is the only build that gets the rounded-playful look without a network dependency. The tradeoff is real but small: the intended typeface renders only for users who happen to have it locally.
- **Opus 5's death sequence is the most animated of the six.** `die()` (`opus-5/index.html:238-245`) fires a screen shake and a white flash simultaneously, forces an upward bounce by clamping `vy` to at most -120 so the bird pops before falling, swaps the eye to a drawn X (`opus-5/index.html:377-380`), and decays the shake and flash on independent timers. The game-over card then tweens in via `overAlpha`, and restart is gated on `overAlpha > .9` (`opus-5/index.html:158-160`) — a deliberate input lock that stops the click which killed you from instantly restarting the run. kimi-k3 and GLM both animate their cards; neither gates the restart input this way.
- **One dead-code ordering quirk in Opus 5, with no runtime effect.** The `rr()` helper that calls `ctx.roundRect` is defined at `opus-5/index.html:90`, one line *before* the `roundRect` polyfill that backfills it for older browsers (`opus-5/index.html:91-97`). This looks inverted but is harmless: `rr` is an arrow function whose body only runs when called, and the first call happens inside the render loop long after both statements have executed. Comparable to kimi-k3's `p.x -= 0` leftover — a cosmetic ordering wart rather than a bug.


**Opus 5 and kimi-k3 tie at 4.75, and they get there by opposite routes.** Opus 5 gives up a point on Collision (AABB approximation rather than the exact clamped circle-vs-rect test) and takes it back on Offline-safe (no Google Fonts dependency vs kimi-k3's). On Polish both land at 4.5 for different reasons: kimi-k3 ships audio with no mute; Opus 5 ships mute but never persists the best score it displays. If you weight offline-safety and the mute control, Opus 5 edges it; if you weight exact collision and a best score that survives reload, kimi-k3 does. On cost they are not close — kimi-k3's ~198 quality/$ is roughly 4.3x Opus 5's ~46.

## Verdict

**kimi-k3 is the pick, not GLM 5.2.** On raw quality alone the mean puts GLM 5.2 a hair ahead (4.83 vs kimi-k3's 4.75 — GLM's edge is its mute toggle and exact collision math paired with real audio, kimi-k3 loses a little for shipping audio with no way to mute it), and the top four are tightly bunched (4.83 / 4.75 / 4.75 / 4.67: GLM, kimi-k3, Opus 5, GPT-5.6 Sol). But a 0.08-point gap on a 1–5 scale isn't a real quality difference, and it comes at 2x the price: kimi-k3 is $0.024 against GLM's $0.048, for a build that matches it on Collision, Architecture, Resize robustness, and Spec/cute, and gives up half a point only on Polish (no mute) and one point on Offline-safe (both pull the same Google Fonts dependency, so this isn't even a real gap between the two). Called on raw score, GLM 5.2 wins by a rounding error; called on what you'd actually reach for, kimi-k3 wins by 2x the value for essentially the same game.

**Opus 5's real result is density, not rank.** It ties kimi-k3 on the scorecard using 497 lines against kimi-k3's 880 and GLM's 799 — the shortest build in the benchmark, and the only one that is simultaneously silent-capable (mute toggle), fully offline, and DPR-aware with a bounded cap. Nothing is stubbed to get there: audio, medals, adaptive difficulty on three axes, screen shake, flash, a tweened game-over card, and a restart input-lock all ship. The two things it leaves on the table are one `localStorage` line and the exact collision test.

Price is why kimi-k3 wins the overall call. At $0.024 it's the second-cheapest build in the whole set, and it ties for second on raw quality — its quality-per-dollar (~198) beats GLM's (~101) by roughly 2x, Opus 5's (~46) by ~4.3x, and Fable 5's (~10.5) by nearly 19x, while giving up almost nothing on the scorecard. GLM 5.2 is the raw-quality ceiling, but it's not worth double the price for a 0.08-point mean edge that comes down to a mute button. **Opus 5 (~46 quality/$) is the best of the expensive tier**, beating GPT-5.6 Sol (~31) on both quality and cost and beating Fable 5 (~10.5) by more than 4x at a fraction of the price — if you are already paying Opus-tier rates, this is the strongest build at that price point. **GPT-5.6 Sol** is now the weakest value in the premium tier and the only one of the six that's completely silent — a real gap for a "cute" flappy bird, whatever its collision math gets right. **DeepSeek** still wins quality-per-dollar outright at ~4,475, at the cost of the resize bug and least-tuned collision box. If the axis is quality-per-dollar with a real quality floor, kimi-k3 is the pick to beat; if it's most game per line of code, Opus 5 wins by a distance; if budget is genuinely no object, GLM 5.2's mean is the highest on paper, but that lead is thin enough that it shouldn't be read as a clear win.

## Limitations

- n=1 per model, no re-rolls, no variance estimate. A single regeneration could move any score.
- The Node `vm` shim proves the logic runs; it isn't a real browser, so nothing here confirms actual frame pacing, touch input, or that any model's audio truly plays.
- kimi-k3, GPT-5.6 Sol, and Opus 5 were evaluated by static read and the automated `vm` smoke test only for this update — unlike Fable 5, GLM 5.2, and DeepSeek, none was hand-played in an actual browser, so their Scorecard rows reflect code-level judgment, not a played impression. That's the same caveat the third-view-car-game benchmark in this repo flags for its static-read-only scores. For Opus 5 specifically this means its "cute" score is read off the drawing code (blush, hair tuft, X-eyes on death, medal labels) rather than off a rendered frame, and its ~626 draw calls/frame have not been checked against real frame timing on a low-end device.
- GPT-5.6 Sol's cost (~$0.15) and Opus 5's (~$0.1039) are formula estimates (bytes ÷ 4 × published output price), not user-reported like the other four; treat both as floors, not metered figures. Opus 5's floor is the least reliable of the two because Opus 5 runs with thinking enabled by default, and reasoning tokens are billed as output but never appear in the kept file — the real number is very likely higher, and the Quality/$ figure of ~46 should be read as an upper bound that falls if the metered cost comes in above $0.1039.
- "Spec/cute", "Architecture", and "Polish" are disclosed aesthetic/code judgment, not measurements, unlike the collision-math, resize, audio, and persistence findings, which are cited directly from source.
